# Evaluation

Code: `tests/eval/` · Results: `tests/eval/results/` (`*_latest.md` + timestamped JSON)

## Dataset (frozen): `tests/eval/dataset/qa.jsonl`

Built once by `build_dataset.py` (seed 42) and reused by every eval, so results are comparable
when the prompt, k, or planner change. Rebuild only on purpose with `--force`.

| Type | Count | How |
|---|---|---|
| single | 80 | ~7 sampled chunks per book; a Groq model writes one paraphrased question + reference answer; gold = that chunk |
| multi | 10 | two related chunks from different books (dense similarity 0.70-0.95); one comparison question; gold = both |
| unanswerable | 10 | hand-written (Boeing 787 checklist, capital of France, ...); gold = none |

Questions are generated by Groq models (`gpt-oss-120b`, `gpt-oss-20b`, `qwen3.8-27b`), not by Mercury 3,
so the answer model is not graded on its own questions. One question was reworded by hand (marked `edited`).

**Relevance rule** (`common.is_relevant`): a retrieved chunk is relevant if it is from the same book and its
pages overlap the gold chunk's pages (chunks overlap 15 %, so a neighbour chunk carries the same facts).

## 1. Retrieval: `uv run python -m tests.eval.eval_retrieval`

| Metric | Meaning |
|---|---|
| Hit@k | any gold chunk in the top k |
| Recall@k | share of gold chunks in the top k (multi rows have 2) |
| Precision@k | share of the top k that are relevant |
| MRR | mean of 1 / rank of the first relevant result |

Results (90 answerable questions):

| Setup | MRR | Hit@1 | Hit@5 | Recall@5 | Recall@10 | Precision@5 |
|---|---|---|---|---|---|---|
| dense only | 0.750 | 0.633 | 0.911 | 0.894 | 0.956 | 0.304 |
| BM25 only | 0.752 | 0.622 | 0.911 | 0.894 | 0.928 | 0.296 |
| hybrid (RRF) | 0.829 | 0.744 | 0.944 | 0.922 | 0.961 | 0.318 |
| **hybrid + planner (app)** | **0.835** | **0.744** | **0.956** | **0.944** | **0.961** | **0.327** |

Precision@5 is capped near 0.2-0.4 because most questions have one gold chunk (plus page neighbours).

## 2. Latency: `uv run python -m tests.eval.eval_latency`

Full pipeline, 100 questions, sequential, after one warm-up:

| Stage | p50 | p95 | max |
|---|---|---|---|
| planner | 525 ms | 686 ms | 905 ms |
| embed query | 48 ms | 100 ms | 111 ms |
| Qdrant search (text + figures) | 33 ms | 41 ms | 46 ms |
| LLM answer | 583 ms | 903 ms | 1,318 ms |
| **end-to-end** | **1.23 s** | **1.69 s** | **2.02 s** |

Target p95 <= 5 s: **pass** (100 % of answers under 5 s).

## 3. Generation: `uv run --group eval python -m tests.eval.eval_generation [--skip-ragas]`

Every question runs through the real pipeline, then is judged by Mercury 3.

| Metric | Source | Result |
|---|---|---|
| Faithfulness | Ragas | **0.982** |
| Answer relevancy | Ragas | 0.913 |
| Context precision (with reference) | Ragas | 0.855 |
| Context recall | Ragas | 0.960 |
| **Hallucination rate** (faithfulness < 1, i.e. >= 1 unsupported claim) | from Ragas faithfulness | **9.9 %** |
| Severe hallucination (faithfulness < 0.5) | from Ragas faithfulness | **0 %** |
| **Citation accuracy** (cited chunk supports its sentence) | custom judge | **0.79** (370 pairs, 86/87 answers) |
| Invalid citation rate | code | 0 % |
| Answers without citation | code | 0 % |
| Unanswerable correctly refused | code | **100 %** |
| Answerable wrongly refused | code | 3.3-6.7 % (two runs) |

Citation accuracy is custom because Ragas checks claims against all retrieved chunks together, not
whether `[n]` specifically supports its sentence. `--skip-ragas` re-runs only citations and refusals (~3 min).

## Notes

- `ragas_compat.py`: ragas 0.4.3 imports a VertexAI class removed from langchain-community 0.4;
  the shim registers an empty placeholder (used only in an `isinstance` check). Evals only.
- Ragas' answer relevancy asks for 3 generations; Mercury returns 1, so that score is slightly noisier.
- The judge is paced (2 concurrent calls, back-off on HTTP 429) because of Mercury's per-minute limit.
